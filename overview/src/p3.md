P3 owns the project's keys and signing: the MSS's hardware security module (HSM) and offline backup, MAVLink key provisioning and rotation, signed and non-rollback CC updates, and encryption of imagery and flight logs to MSS-held keys (P1 `docs/07-requirements.md` §7.1; P1 `README.md`). It also hosts the PX4 software-in-the-loop (SITL) harness for VE-01, VE-02 and VE-17, because it owns MAVLink key provisioning (P1 `docs/08-verification-plan.md`). VE-02 closes P1's open item OI-01: until it passes, end-to-end MAVLink signing from GCS to FC is design intent only (P1 `docs/04-architecture.md` §4.5). P3 owns {{p1.repo_reqs:P3}} requirements.

**Inherited from P2.**

- **Custody of P2's keys** (P2 `docs/05-key-management.md` §5.1, §5.3). P3 generates production keys matching P2's key table, in an offline root tier (K-CC-ROOT, K-FC-REC) and an HSM-held intermediate tier (K-CC-OS, K-CC-POL, K-FC-FW), and swaps each file-based signer for an HSM signer: `mkimage -N pkcs11` for FIT configurations and a PKCS#11 ECDSA signer for the approved policies, so that K-CC-POL, the key that decides which CC boot states get the keys, moves into the HSM (P2 `docs/03-measured-boot-sealing.md` §3.3, §3.5).
- **OI2-04:** PX4's `sign_firmware.py` needs the raw Ed25519 private key; SR-034 needs signing inside the HSM, so P3 needs a PKCS#11 Ed25519 signer that writes the same 64-byte signature PX4 appends (P2 `docs/04-fc-secure-boot.md` §4.6).
- **OI2-05:** committing a new anti-rollback epoch uses TPM owner authorization in P2; a fielded CC needs an MSS-signed authorization so that no long-lived secret is stored on the CC (P2 `docs/03-measured-boot-sealing.md` §3.4, §3.9).
- **Update acceptance (SR-007):** each CC release ships its signed approved policy; P3 includes it in the signed update metadata and owns update acceptance, and shares the A/B layout that lets a CC fall back when a new chain cannot unseal with P4 (P2 `docs/03-measured-boot-sealing.md` §3.5; `docs/05-key-management.md` §5.3).
- **FC rollback (THR-066):** P2 found that PX4 Bootloader Secure Boot never checks a version; P1 added THR-066 and SR-045, verified by P3's VE-17, in which the GCS refuses to arm a vehicle whose FC reports older firmware (P2 `docs/01-scope-and-trace.md` §1.4, change 2).
