# 1. System description

The system is a notional, unclassified small UAS for a generic survey/ISR mission. It flies a pre-planned pattern, collects EO imagery, streams video to the operator, and returns. It is assembled from public, open-source components (A-01). It exists to give P1–P6 a single target to secure.

## 1.1 Scope

**In scope:**
- **Air vehicle:** flight controller, companion computer, payload, navigation sensors, actuators and air radio.
- **Ground segment:** ground control station and ground radio.
- **Maintenance and support station:** used to build, load and provision the system.
- **Data flows** among all of the above.

**Out of scope:** airworthiness, the radio waveform, EW countermeasures beyond detection and resilience, Remote ID, UTM (A-12), and any separate RC link (A-07).

## 1.2 Components

The full element list, including data flows, data stores and trust boundaries, is [`data/elements.csv`](../data/elements.csv).

| ID | Component | Basis | Security-relevant functions |
|---|---|---|---|
| CMP-FC | Flight controller | PX4 on NuttX, Pixhawk-standard FMU (A-03) | Flight control and failsafes. Verifies and signs MAVLink. Holds the signing key on its SD card |
| CMP-CC | Companion computer | Generic ARM64 Linux single-board computer (A-04) | WireGuard endpoint; accepts only WireGuard on its radio interface (SR-001). MAVLink router with allowlist and a custom command filter (DD-04). Onboard autonomy and payload control. Holds the signing key |
| CMP-PL | EO payload | Generic USB or CSI camera | Produces imagery and video |
| CMP-NAV | GNSS and compass | Civil GNSS receiver plus magnetometer (A-10) | Position and heading source |
| CMP-ACT | ESCs and motors | PWM/DShot or DroneCAN | Propulsion |
| CMP-RAD-A, CMP-RAD-G | Data-link radios | Generic IP radios | Untrusted transport (A-05) |
| CMP-GCS | Ground control station | QGroundControl on a Linux laptop | Planning, C2, telemetry and video display. Holds the signing key |
| CMP-MSS | Maintenance and support station | Linux workstation, wired connections only | Builds, signs and loads software. Provisions keys. Receives offload. Holds the signing key |

## 1.3 Key material

| Key | Mechanism | Held by | Provisioned | Notes |
|---|---|---|---|---|
| MAVLink signing key | One shared 32-byte secret. Each frame carries a 48-bit signature: SHA-256 over the key and the frame [MAV-SIGN] | FC, CC, GCS, MSS | By the MSS over wired links. The FC's first key goes in over USB while disarmed (A-14) | No per-node identity and no automatic rotation (§4.2) |
| WireGuard key pairs | Curve25519, one pair per endpoint [WG] | GCS and CC each hold their own private key and the peer's public key | Generated by the MSS and loaded over wired links | Confidentiality and peer authentication across TB-01 (DD-02) |
| Software signing keys | Defined in P2 and P3 | Private keys on the MSS; public keys on the devices | P2, P3 | Candidate for the FC: PX4 Bootloader Secure Boot (Ed25519) [PX4-SECBOOT] |
